DHWANI-KAVACHAGENDA
Problem statement

Voice is now a bank’s weakest channel

  • Voice cloning is trivial. Seconds of a customer’s or RM’s voice → a clone that authorises transfers.
  • Most vishing needs no deepfake. A real human scammer coerces a real customer — the larger share of losses.
  • The money moves during the call. Post-call detection is too late.
  • Volume & languages. Millions of calls in Hindi/English/code-mixed — humans can’t screen them.

Why current defenses fail

× OTP — the victim reads it out under pressure.

× Voice biometrics — a good clone passes; can’t judge a coerced caller.

× Manual agents — can’t hear a deepfake or catch a practised scammer.

DHWANI-KAVACHTHE PROBLEM
The threat, precisely

Two attack vectors — most tools see only one

1 · Synthetic voice (deepfake)

An AI clone of a real person’s voice. Sounds like the customer or RM. Passes voice biometrics. Used to authorise transfers or reset credentials.

Detected by our neural voice engine.

2 · Human social engineering

A real human scammer with a script: urgency, authority impersonation, isolation, OTP requests, threats. No deepfake — so deepfake-only detectors score it safe.

Detected by our scam-script LLM layer.

A real defense must cover both. That is the core of our design.

DHWANI-KAVACHTHE THREAT
The insight

We didn’t build a deepfake detector.
We built a fraud shield.

A deepfake detector is a commodity and it is narrow. The fraud that drains accounts is broader — clones and human scam scripts, on real phone lines, in Indian languages.

Our edge is everything a detector isn’t: the decision, the deployment, and the intelligence around it.

DHWANI-KAVACHSOLUTION OVERVIEW
How it works

A layered, fail-safe pipeline

Two entry points, one engine

Live WebSocket stream (4s window / 2s hop) & REST file upload run the same detection engine.

Fail-safe composition

Every advanced layer is additive: if STT, the LLM, or the model file is missing, that layer returns neutral and the core verdict still ships.

Real-time under load

Inference runs off the event loop; only the newest window is scored (backlog discarded) so a slow CPU never floods the client.

Explainable output

Every verdict: 0–100 score, per-layer breakdown, scam tactics, novelty, campaign match, and a plain-English reason.

DHWANI-KAVACHDETECTION LAYERS
Deep dive · model & the generalization lesson

Why one detector wasn’t enough

  • v1 was a single wav2vec2: ~4% EER on ASVspoof/Kaggle dev sets — looked great.
  • Measured on real ElevenLabs clones + real voices it was near-random: AUC 0.63 — a textbook out-of-domain failure (Müller et al., Interspeech 2022: SSL detectors degrade 200–1000% cross-domain).
  • Fix: two independent XLS-R detectors + fusion — a codec/artifact specialist and a clone specialist.
On our labeled real-vs-clone setEERAUC
v1 — single wav2vec2 (measured)40%0.63
current — dual XLS-R + fusion~6.7%0.996

The lesson that drives the design: never trust one detector’s leaderboard number.

DHWANI-KAVACHMODEL & GENERALIZATION
Deep dive · scam-script layer

Catching the human scammer

  • Pipeline: rolling audio → Whisper speech-to-text → Nemotron LLM → scam score + tactics.
  • Tactics: urgency authority impersonation isolation new-beneficiary OTP/PIN request threat
  • Runs in the background every ~4s over the last ~8s — never blocks the 2s detection cadence.
  • Multilingual: Whisper auto-detects language; the LLM reasons in Hindi & Hinglish. Verified: Hindi scam → 90/100.
  • Fail-safe: no key / no STT / offline → neutral; voice detection unaffected.
DHWANI-KAVACHSCAM-SCRIPT
Deep dive · decision fusion

From scores to an auditable decision

threat = voice≥70 OR scam≥70 OR novelty≥0.6 high_value = new payee OR amount ≥ ₹50,000 BLOCK if threat AND high_value CHALLENGE if threat MONITOR otherwise
  • Transaction context makes the response proportionate — a suspicious voice on a balance check ≠ on a ₹5-lakh transfer.
  • Rule-based on purpose: every decision is defensible to an auditor. A learned policy needs outcome data we must first accumulate.
  • Each action ships a plain-English reason; thresholds tune to risk appetite.
DHWANI-KAVACHDECISION FUSION
Deep dive · novelty & campaigns

Zero-day defense & fraud-ring intelligence

Novelty / zero-day

Uses the model’s own uncertainty: novelty = 1−|2p−1|. A signature unlike anything trained on lifts GREEN → AMBER.

Catches the clone tool that doesn’t exist yet. (Heuristic; embedding-OOD is the upgrade.)

Campaign detection

Each call gets a 768-d voiceprint (same forward pass, free). Cosine-match links the same voice across calls into a campaign; a prior-fraud voiceprint is blocklisted on its next call.

“The same synthetic voice hit 14 customers.”

DHWANI-KAVACHNOVELTY & CAMPAIGNS
Deep dive · telephony (in progress)

Real phone lines — the hard part, honestly

  • Real calls are 8 kHz, band-limited (300–3400 Hz), G.711 µ-law, and lossy.
  • We built a channel-robust training pipeline (train_robust.py) that degrades audio on the fly, and an A/B eval harness (eval/run.py) that measures the phone-line cost.
  • Measured today: telephony is still a weakness — AUC ~0.62–0.82 vs 0.996 clean.
  • We show this honestly — the pipeline to close the gap is built; more diverse channel data is the next run.

DHWANI-KAVACHTRUST & GOVERNANCE
Honest limitations & future work

What’s a v1 today — and the upgrade path

  • Small eval set (30 clips) → directional; a large fixed benchmark is in progress (harness built).
  • Telephony is a measured weakness (AUC ~0.62–0.82) → channel-robust retraining is the fix.
  • Out-of-domain studio real voices false-positive → needs more diverse real data.
  • Default ensemble under-performs its neural core → deploy calibration + fusion (EER 20% → 13% → 3%).
  • Thresholds (0.85, calibration, fusion) tuned on thin data → refit at scale.
  • LLM is a cloud call → on-prem NIM container (base-URL change).
  • Customer voice-identity not built yet; adversarial-evasion untested.

We’d rather show you the roadmap than pretend it’s finished.
